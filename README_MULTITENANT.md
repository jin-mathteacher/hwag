# 멀티테넌트 시스템 사용 가이드

## 개요
이 시스템은 강사별로 클래스를 관리하고, 각 클래스의 실습 데이터를 분리하여 관리할 수 있는 멀티테넌트 구조입니다.

## 주요 기능

### 1. 로그인 시스템
- **강사 로그인**: 사용자명, 비밀번호, 클래스 선택
- **총 관리자 로그인**: 전체 데이터 관리 권한
- **클래스 관리**: 강사가 자신의 클래스를 생성/삭제 가능

### 2. 데이터 분리
- 각 클래스의 실습 데이터가 완전히 분리됨
- 클래스별로 독립적인 데이터 저장
- 실습 1(워드크라우드)과 실습 2(담벼락) 데이터 분리 관리

### 3. 총 관리자 기능
- 모든 강사의 클래스 데이터 확인
- 클래스별 데이터 다운로드
- 전체 데이터 일괄 내보내기
- 통계 대시보드

## 사용 방법

### 강사 로그인
1. `login.html` 접속
2. "강사" 탭 선택
3. 사용자명 입력 (예: "teacher1")
4. 비밀번호 입력 (현재는 검증 없음)
5. 클래스 선택 또는 새 클래스 생성
6. 로그인 버튼 클릭

### 클래스 생성
1. 강사 로그인 화면에서 사용자명 입력
2. "새 클래스 추가" 버튼 클릭
3. 클래스 이름 입력 (예: "2026년 1기")
4. 설명 입력 (선택사항)
5. "추가" 버튼 클릭

### 총 관리자 로그인
1. `login.html` 접속
2. "총 관리자" 탭 선택
3. 사용자명: `admin`
4. 비밀번호: `admin123`
5. 로그인 버튼 클릭

### 총 관리자 기능
- **대시보드**: 전체 통계 확인
- **강사별 클래스 목록**: 각 강사의 클래스와 데이터 확인
- **데이터 보기**: 클래스별 상세 데이터 확인
- **데이터 다운로드**: 클래스별 JSON 파일 다운로드
- **전체 내보내기**: 모든 데이터를 하나의 파일로 내보내기

## 데이터 구조

### 저장 키 형식
- 클래스 데이터: `class_data_{CLASS_ID}`
- 강사 클래스 목록: `teacher_classes_{USERNAME}`
- 사용자 ID: `user_id_{CLASS_ID}`

### 데이터 구조
```json
{
  "practice1": {
    "words": {},
    "participants": [],
    "lastUpdate": 1234567890
  },
  "practice2": {
    "notes": [],
    "participants": [],
    "lastUpdate": 1234567890
  }
}
```

## 보안 고려사항

⚠️ **현재는 프론트엔드 기반의 데모 버전입니다.**

실제 운영 환경에서는:
1. **백엔드 서버 구축** 필요 (Node.js, Python 등)
2. **실제 인증 시스템** 구현 (JWT, 세션 관리)
3. **데이터베이스** 사용 (MySQL, PostgreSQL, MongoDB 등)
4. **HTTPS** 적용
5. **비밀번호 암호화** (bcrypt 등)
6. **권한 관리** 시스템

## 향후 개선 사항

1. **백엔드 API 구축**
   - RESTful API 또는 GraphQL
   - 데이터베이스 연동
   - 인증/인가 시스템

2. **실시간 동기화**
   - WebSocket 또는 Server-Sent Events
   - 여러 사용자가 동시에 작업할 때 실시간 업데이트

3. **데이터 백업**
   - 자동 백업 시스템
   - 데이터 복구 기능

4. **보고서 생성**
   - PDF/Excel 형식의 보고서 생성
   - 통계 차트 및 그래프

5. **사용자 관리**
   - 강사 계정 관리
   - 권한 세분화

## 문제 해결

### 로그인 후 실습 페이지 접근 불가
- 세션이 제대로 저장되었는지 확인
- 브라우저 개발자 도구에서 `sessionStorage` 확인

### 클래스 데이터가 보이지 않음
- `localStorage`에서 `class_data_{CLASS_ID}` 키 확인
- 클래스 ID가 올바른지 확인

### 총 관리자가 데이터를 볼 수 없음
- `localStorage`에 데이터가 저장되어 있는지 확인
- 강사가 먼저 클래스를 생성하고 데이터를 입력했는지 확인
